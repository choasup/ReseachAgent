## 2. 方法学（口径与公平性）

- **推理**：8 个模型走 vLLM serve（OpenAI 兼容 API，16 并发；采样参数用各模型自带
  generation_config，公平且零维护）；Molmo 走 transformers（含 ROCm 补丁）。
- **判分**：VQA/OCR/计数走规则；MCQ/Y-N 的答案抽取统一用**本机 LLM-judge**
  （`exact_matching` 对冗长输出系统性漏判：Qwen3 MMMU 21%→66%——详见首版报告章节，
  修正可信性验证：翻负=0、简洁模型零变化）。
- **ROCm 适配**：eager attention（gfx942 SDPA 视觉塔静默算错）、Conv2d/3d(kernel==stride)
  →matmul（MIOpen 段错误）、get_gpu_memory 补丁。全部固化在 `scripts/patch_vlmevalkit.py`。
- **巡检基准**：339 题 Y/N、7 场景、红圈标注 inpaint 防作弊，详见 `INSPECTION_REPORT.md`。

## 4. 对自建 benchmark 与业务的结论

1. **出题重点**（区分度最大）：图表数值读取（分差 44）、OCR（分差 39）、学科多步推理
   （分差 28）、巡检类真实场景（两榜错位的核心证据源）。
2. **巡检业务选型**：InternVL3-8B 与 Qwen3-VL-8B 起点最高，但 60 分意味着都必须
   微调/提示工程后才可用；建议下一步做"正常参照描述"提示对照实验 + V*/SEAL 式
   两段法（先定位后判断）验证，然后走少样本微调。
3. **学术定位**：远距监控单帧多目标巡检判断在学术界是空白（MMAD 工业近拍、
   FoodMonitor 视频时序），26k 已标注巡检图有发表/开源价值。

### R3.2 ZwZ-8B（内化 zoom 的 Qwen3-VL-8B）验证 —— 本轮核心发现

| 视角 | Qwen3-VL-8B（基座） | ZwZ-8B | 差值 |

| 　巡检正常特异 | 87% | 59% | -28 |
| 　巡检 F1（估） | ~0.44 | **~0.60** | +0.16 |

**解读**：
1. 巡检总分持平掩盖了**行为质变**——ZwZ 把"保守漏报"（yes 率 22%）校准到接近真实

2. 分场景：清洁类大涨（制作区 82 全场最高、客区 +16），人物合规类回落（物料摆放 52

3. 公共常规基准零损失（-0.4 噪声内）——增强没有牺牲通用能力。
4. **落地路径明确**：以 ZwZ-8B 为起点（或复刻 R2I 配方 + 自有巡检数据），
   优先补人物合规类样本，特异性通过阈值/二段复核找回。

## R5 Round5（2026-07-21/22）：Qwen3-VL-235B 评测 + 三个判分链路 bug 的修正

### R5.1 本轮结论：规模没有带来预期收益

评测对象 **Qwen3-VL-235B-A22B-Thinking-FP8**（TP=4，vLLM serve，无工具单次前向）。
结果是**三张榜单一个第一都没拿到**：

| 榜单 | 235B 名次 | 分数 | 榜首 |
|---|---|---|---|
| 通用榜（9 项公开基准均分） | 第 3 / 11 | 78.6 | Qwen3-VL-8B-Instruct 81.0 |
| 细粒度套件（GP-Avg） | 第 3 / 11 | 65.5 | ZwZ-8B 73.1 |
| 巡检榜 | 第 8 / 11 | 53.1 | InternVL3-8B 60.8 |

- **强项**：CountBenchQA 94.9（全场第一）、RealWorldQA 77.1（全场第一）、HR-8K 73.5（第二）。
- **弱项**：MME-RealWorld-Lite 34.9（第 9）、ChartQA 73.3、DocVQA 87.3、MMMU 60.6——
  后两项均低于自家 8B（95.7 / 66.1）。
- **口径声明**：我方 8B 为 Instruct 版、235B 为 Thinking 版，属不同后训练路线，
  **不是干净的规模对照**。要论证"规模无用"需补测 235B-Instruct 版。

结合 R4 的结论，"细粒度感知靠训练方式而非参数量"这一判断在更大规模上再次得到支持：
一个 8B 的 R2I 蒸馏模型（ZwZ）在细粒度套件上领先 235B 达 7.6 分。

### R5.2 查出并修复的三个判分链路 bug（影响历史数据）

本轮最重要的产出不是分数，而是三个此前未被发现的判分错误。

**① BabyVision 答案编码错误（影响全部 11 个模型的历史结果）**
自建 TSV 时把源数据的 `choiceAns`（**0 起的选项下标**，如 3.0 表示 D）直接写入 answer 列，
判分器拿 "3" 比对模型输出的 "D"，恒不匹配。**全场分数被压到 0-6 分**，看起来像
"这个基准特别难"，完全符合预期，因此隐藏了十天。
暴露它的是 235B 拿到 0.00——0 分在统计上不可能，才触发排查。

修复后真实成绩（135 题选择）：Idefics3 / InternVL3 32.6、Qwen2.5-VL 31.1、ZwZ 30.4、
GLM / Qwen3-8B 29.6、Ovis2 28.1、LLaVA-OV 27.4、Pixtral 25.2、molmo 21.5、**235B 20.7（垫底）**。
4-6 选项的随机水平约 17-25%，即**所有模型基本等于瞎猜**——与 BabyVision 论文
（arXiv 2601.06521）"最强模型仍落后六岁儿童约 20%"的结论一致。

> 修这个 bug 需要连清三层：数据文件 → 已产出的评分文件 → **判分结果 pkl 缓存**。
> 前两次"已修复"都是空跑，因为 VLMEvalKit 看到 index 已在缓存中就跳过重算。

**② Blank 判分截断（影响所有输出冗长的模型）**
`simple_blank.py` 取预测文本的**前** 400 字符送 judge，而思维链模型的答案在末尾，
被整段截掉。抽查 253 题中有 22 题答案字面正确却判 0。
已改为剥离 `<think>` 段 + 保留首尾。

**③ 思维链污染规则判分（仅影响 Thinking 版模型）**
DocVQA / ChartQA 用 ANLS / relaxed accuracy 做字符串匹配，面对 Thinking 版
输出的整段推理直接崩溃：**ChartQA 0.0、DocVQA 4.91**。抽查确认模型算出的
"0.57" 与标准答案完全一致仍判 0；2500 题中 2228 题带 `</think>` 标记。
增加清洗步骤（按 `</think>` 切出最终答案，原文件留 `.rawthink` 备份）后：
**ChartQA 0.0 → 73.3、DocVQA 4.91 → 87.3**。

> 推论：公开榜单上 Thinking 版模型的分数，若评测方未做同等清洗，可能被系统性低估。

### R5.3 被证伪的假设（记录以免重蹈）

一度怀疑 235B 成绩偏低源于生成截断，据此把上下文从 32k 扩到 128k 并全量重跑 14 个数据集。
**结论：假设错误。** 用于判定截断的启发式（"无 `</think>` 且长度 > 150"）本身有误——
向 API 索取 `finish_reason` 后发现被标记的样本以 `\boxed{A}` 干净收尾、`finish_reason: stop`。
重跑前后除 BabyVision（编码修复，+20.7）外全部落在 ±2 噪声内：
V\* +2.1、ZoomBench −1.1、MMMU +0.6、MMStar +0.6、RealWorldQA −0.1。

**教训**：自建基准应加一条自检——**任何模型在选择题上低于随机水平，先怀疑判分链路，
而不是模型能力**。
