# 巡检场景 Benchmark（Inspection v0）— 测试用例与评测报告

> 用真实餐饮门店监控画面，测 VLM「无提示发现巡检异常」的能力。
> 数据源：门店运营巡检审核数据（目录结构即人工标注）· 构建日期 2026-07-08
> 已评模型：Qwen3-VL-8B-Instruct / GLM-4.1V-9B-Thinking / Molmo-7B-D（judge 修正口径）

## 1. 摘要

- **339 题 Y/N 判断**（yes=164 / no=175），7 个真实巡检场景，28 个异常子类。
- **三模型全部接近随机线**（50）：Qwen 60.2 > Molmo 56.6 > GLM 54.6。
- **失败模式高度一致 = 系统性漏报**：正常画面判得准（No 特异性 84–100%），
  异常几乎看不见（整体答 yes 率仅 9–22%，而真实异常占 48%；垃圾桶场景召回 0%）。
- **结论：通用 VLM 开箱做巡检异常发现不可用**，需要「正常参照」提示工程 / 少样本 / 微调。
  这同时验证了该 benchmark 的区分度与业务价值。

## 2. 数据集构成（339 题）

| 场景 | 题数 | 正(异常) | 负(正常) | 异常子类 |
|---|---|---|---|---|
| 垃圾桶 | 50 | 25 | 25 | 未加盖 9 · 满溢 8 · 盖板未闭合 8 |
| 客区清洁 | 50 | 25 | 25 | 地面垃圾 13 · 桌面垃圾 12 |
| 制作区清洁 | 50 | 25 | 25 | 台面垃圾 9 · 洗手池 8 · 清洗池 8 |
| 仪容仪表 | 50 | 25 | 25 | 玩手机/倚靠 6 · 无工牌 5 · 鞋色 5 · 裤色 5 · 无工帽 4 |
| 摄像头质检 | 50 | 25 | 25 | 关键区不可见(料理机/水池/茶桶架/出餐/咖啡) 22 · 遮挡 2 · 需调整 1 |
| 物料摆放 | 50 | 25 | 25 | 客区放垃圾/垃圾袋/物料/扫把/纸箱/拖布车 20 · 未离地 3 · 不规范 2 |
| 人员状态 | 39 | 14 | 25 | 个人物品放置制作区 14（源图仅 14 张） |

**题目形式**：每场景一个固定中文判断题（保证场景内可比），如：
> 这是餐饮门店的监控画面。图中垃圾桶是否存在满溢、未加盖或盖板未闭合等异常？请回答 yes 或 no。

**判分**：VLMEvalKit Y/N 口径（与 POPE 相同），LLM-judge 抽取答案（与公共基准一致）。

## 3. 构建方法与防作弊处理

1. **目录即标注**：运营审核后的异常图按子类归档、无异常图单独归档——GT 无需人工重标。
2. **红圈捷径消除（关键）**：原始异常图带人工画的红色圈注。若不处理，模型可
   「见红圈答 yes」作弊。做法：HSV 红色细线检测 + 线状连通域过滤（防误伤灭火器等
   红色实物）+ TELEA inpaint。164 张正样本中 152 张检出并修复（目检无痕）；
   未检出的 12 张主要为摄像头质检类——该类异常是画面整体（遮挡/角度），原图本就不画圈，合理。
3. **正负均衡 + 子类分层采样**：每场景正负各 25（人员状态正样本仅 14），异常按子类轮转采样保覆盖。
4. 图片统一缩至长边 ≤1024、JPEG q85，随机打乱顺序。

## 4. 评测结果

### 4.1 总分（随机基线 = 50）

| 模型 | Overall | 答 yes 率（真实 48%） | 判读 |
|---|---|---|---|
| Qwen3-VL-8B | **60.2** | 22% | 最好，但漏报仍严重 |
| Molmo-7B-D | 56.6 | 9% | 几乎全答"无异常" |
| GLM-4.1V-9B | 54.6 | 11% | 同上 |

### 4.2 分场景（acc / 异常召回 / 正常特异性）

| 场景 | Qwen | GLM | Molmo |
|---|---|---|---|
| 物料摆放 | **74** / 64 / 84 | 62 / 32 / 92 | 58 / 40 / 76 |
| 制作区清洁 | 66 / 40 / 92 | 54 / 8 / 100 | 66 / 32 / 100 |
| 摄像头质检 | 64 / 28 / 100 | 52 / 4 / 100 | 56 / 12 / 100 |
| 人员状态 | 59 / 14 / 84 | 64 / 7 / 96 | 67 / 7 / 100 |
| 仪容仪表 | 56 / 64 / 48 | 50 / 40 / 60 | 50 / 0 / 100 |
| 客区清洁 | 52 / 4 / 100 | 52 / 4 / 100 | 52 / 4 / 100 |
| 垃圾桶 | 50 / **0** / 100 | 50 / **0** / 100 | 50 / **0** / 100 |

**模式解读**：
- **目标越大越可判**：物料摆放（拖布车/纸箱等大物体入画）召回最高；垃圾桶（远距小目标、
  需判断"有没有盖"）三模型召回全部为 0。
- **特异性普遍 ~100% + 召回个位数 = 保守偏置**：模型对监控画面默认输出"正常"，
  不主动搜寻异常。这与其训练分布（干净的网络图文）一致。
- Qwen 在仪容仪表上召回 64% 但特异性只有 48%（误报换召回）；其余模型该场景直接不报。

### 4.3 典型错例（漏报）

- [垃圾桶/未加盖] GT=Yes → 三模型齐答 "no"（目标远、小，需要"正常应有盖"的先验）
- [物料摆放/物料放置在客区] GT=Yes → Qwen 答 "no"
- [客区/桌面垃圾未清理] GT=Yes → 模型描述画面正常，未注意桌面残留

## 5. 已知局限（v0）

1. **部分远距小目标题目对人类也偏难**：无红圈提示时，垃圾桶/客区一些题目人工也难判。
   垃圾桶/客区场景的绝对分数应谨慎解读；分数间的相对比较仍有效。
2. **客区负样本来源不同**（tencent_clean，水印与正样本不同）——水印语义与任务无关，
   但严格说存在可学的分布差异。
3. 人员状态正样本仅 14 张；营销物料场景（85 张、无负样本）未纳入。
4. 单帧判断，未利用监控的时序信息。

## 6. v1 改进方向

1. **两级任务**：保留红圈 bbox（构建时可得），增设"局部放大后判断"版本——
   区分「发现」（全图搜索）与「识别」（给定区域判断）两级能力。
2. **人类可判性过滤**：以人工双盲可判为入题门槛，剔除不适定题。
3. **提示工程对照组**：附"正常参照描述"（如"垃圾桶正常状态应加盖"）重测，
   量化 prompt 工程能挽回多少召回。
4. 引入时序（前后帧对比）与多图对照题型。

## 7. 复现

```bash
# 构建（本地，源数据 AI快速检查/）
python build_inspection.py <AI快速检查目录> Inspection.tsv 25
# 注册 + 评测（服务器）
python register_inspection.py <VLMEvalKit根> $LMUData/Inspection.tsv
python run.py --data Inspection --model <模型> --judge gpt-4o-mini --reuse
# 诊断分析
python analyze_inspection.py VLMEvalKit/outputs
```
文件：`scripts/build_inspection.py`（含红圈修复）、`scripts/register_inspection.py`、
`scripts/analyze_inspection.py`。数据集：服务器 `$LMUData/Inspection.tsv`（62MB，339 题）。
