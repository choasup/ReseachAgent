# Inspection v1 设计：HPP 式程序化巡检（Programmatic Inspection Probing）

> 动机：v0 实测三模型接近随机线（系统性漏报：垃圾桶召回 0%、答 yes 率 9-22%）。
> 本设计把 HPP（arXiv 2606.21734，见 papers/2026/2026-07-08-hpp-programmatic-video-probing.md）
> 的"感知-推理解耦 + 层次探查"翻译到巡检场景，全程 training-free，当天可跑。

## 1. 核心转变

```
v0（单次前向）:  整图 + "有没有异常?" → 模型一口气找+判 → 默认"正常"
v1（程序化探查）: 代码执行巡检清单 → 模型只回答局部中性问题 → 规则聚合结论
```

## 2. 管线（四个探查原语）

对每张图、每个场景的巡检项清单逐项执行：

```python
# 伪代码：垃圾桶场景
regions = locate(image, "垃圾桶")            # ① 定位：找出所有目标，返回 bbox
for r in regions:
    crop = zoom(image, r, margin=0.3)        # ② 放大：crop + 上采样到模型舒适分辨率
    lid  = judge(crop, "这个垃圾桶的盖子是盖着的还是开着的？只答：盖着/开着/看不见盖子")   # ③ 中性判断
    full = judge(crop, "垃圾是否高出桶沿？只答：是/否")
    ...
verdict = aggregate(lid, full, ...)           # ④ 规则聚合 → 场景结论（代码判定，非模型）
```

### 原语定义
| 原语 | 实现 | 说明 |
|---|---|---|
| `locate(img, obj)` | VLM grounding 问法（输出 bbox/点）或开集检测器（GroundingDINO 等） | 找不到 → 多尺度重扫一次 → 仍无则记"目标不在画面"（本身可能就是异常，如摄像头质检类） |
| `zoom(img, box)` | 纯图像操作：crop + 边距 + 放大 | 攻克远距小目标 |
| `judge(crop, q)` | VLM 回答**中性、具体、封闭**的问题 | 问法禁止出现"异常/正常/问题"字样，消除先验偏置 |
| `aggregate(...)` | 纯代码规则 | 巡检项→结论的映射是确定性的，可审计 |

### 每场景的 checklist（示例，来自 v0 的 28 个异常子类）
- 垃圾桶：盖子状态 / 是否满溢 / 盖板闭合
- 客区：桌面有无杂物 / 地面有无垃圾
- 仪容仪表：locate(人) → 逐人 zoom → 工牌/工帽/鞋色/是否玩手机
- （摄像头质检类特殊：locate 失败本身即信号）

## 3. 实验设计（同 v0 的 339 题，可直接对比）

| 组 | 配置 | 检验什么 |
|---|---|---|
| v0（已有） | 整图单问 | 基线 |
| **v1a** | locate→zoom→中性judge→聚合 | HPP 式解耦的增益 |
| **v1b** | v1a + 每个 judge 附同场景正常参照图（双图对比） | 叠加 ADSeeker/VisCritic 式参照先验的增益 |
| 消融 | v1a 去掉 zoom（原图直接中性问题） | 分离"放大"和"问法"两个因素的贡献 |

- 判分不变（Y/N + LLM-judge），保证与 v0 可比。
- 主指标：整体 acc + **各场景异常召回**（v0 的死穴）+ 特异性（防止召回换误报）。
- 成本：每题约 2-5 次 VLM 调用（自适应：正常画面走得快），吞吐预算 ~3-4× v0。

## 4. 预期与判读
- 假设 H1：垃圾桶/客区（小目标类）召回大幅回升（0% → 明显非零）——zoom 起效。
- 假设 H2：v1a 的 yes 率从 9-22% 向真实 48% 靠拢——中性问法起效。
- 假设 H3：v1b ≥ v1a——参照先验有额外价值（= ADSeeker 假设的定量验证）。
- 若 H1 成立而 H2 不成立 → 问题在感知不在语言先验；反之亦然。这个分解本身就是产出。

## 5. 失败风险
- locate 对监控画质的鲁棒性（模糊/逆光）；grounding 弱的模型（GLM?）可换检测器兜底。
- 中性问题设计需人工过一遍（避免二义）；每场景 3-5 个 judge 问题足够。
- 多次调用的累计误差：单步错→聚合错，需记录每步中间输出便于归因（HPP 的可诊断性优点顺带继承）。
